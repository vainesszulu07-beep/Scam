Frontend Integration Guide

Learn how to connect your registered application to the ZambianAdvertisements network and display advertisements using the official JavaScript SDK.

1. How the integration works

Your frontend does not communicate directly with the partner verification system. It first contacts your own backend, which verifies your application and returns temporary advertising credentials.

1
Frontend request Your website requests authorization from your backend.
2
Backend verification Your backend verifies your registered application.
3
Receive credentials Your frontend receives the token_id and subid.
4
Load advertisement The SDK uses the credentials to request advertising content.
Important: The SDK handles the advertising iframe and its communication with the advertising platform. Your application does not need to manually create an advertising iframe.

3. Available advertising placements

The SDK supports four advertising placements. Select the placement that best suits the design of your application.

FIXED POSITION

Bottom placement

Displays the advertisement at the bottom of the user's screen. It remains fixed while the user scrolls.

Container required: No

SDK value: "bottom"

FIXED POSITION

Top placement

Displays the advertisement at the top of the user's screen. It remains fixed while the user scrolls.

Container required: No

SDK value: "top"

FULL SCREEN

Fullscreen placement

Displays an advertisement across the entire screen. The SDK temporarily locks page scrolling while it is open.

Container required: No

SDK value: "fullscreen"

INLINE POSITION

Static placement

Displays the advertisement inside a specific location in your webpage. You decide exactly where it appears.

Container required: Yes

SDK value: "static"

Important about static placement: You must create a container in your HTML exactly where you want the advertisement to appear. The SDK searches for that container and inserts the advertisement there. It replaces the container's existing contents.

7. Understanding the SDK response

The SDK returns a result after the advertising platform responds to the initialization request.

Result Meaning Recommended handling
success: true The advertisement was initialized successfully. Continue normal application operation.
noAd: true No advertisement is currently available. Continue without displaying an ad.
closed: true The user closed the advertisement. Continue normal application operation.
success: false Initialization failed. Check the returned error message.

8. Important implementation rules

  • Always request authorization from your own backend before initializing the SDK.
  • Use the actual token_id and subid returned by your backend.
  • Do not invent tokens or use sample credentials in production.
  • Do not store temporary authorization tokens in localStorage or hardcode them into your website.
  • Do not reuse a token when your backend's token rules require a fresh authorization request.
  • For static placement, create the container exactly where the advertisement should appear.
  • Do not use a container for top, bottom or fullscreen placement. The SDK positions those advertisements itself.
  • Check the SDK result and handle errors so that an advertising issue does not break the rest of your website.
Security warning: Never put your partner secret_key, private application credentials, or Supabase secret keys in frontend HTML or JavaScript. Keep these values in your server-side environment or backend code. The frontend should receive only the authorization response required to initialize the SDK.

9. Integration checklist

Before deploying your integration, confirm the following:

  • The official SDK script is included in your webpage.
  • Your backend verification endpoint is working.
  • Your backend returns success and authorized as true when verification succeeds.
  • Your response contains a valid token_id and subid.
  • You selected a supported placement.
  • For static placement, the container exists and its selector is correct.
  • Your frontend handles no-ad and error responses.
  • No private partner credentials are exposed in the browser.
Once these steps are complete, your application can request advertisements through the ZambianAdvertisements SDK.
